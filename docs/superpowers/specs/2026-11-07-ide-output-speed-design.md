# IDE 对话响应平均速率设计

日期：2026-11-07
状态：用户已批准并完成实现；自动测试、编译及打包通过，用户已确认 IDE 速率显示和防闪烁效果。

## 1. 目标与范围

在 Claude Hub 面板及 VS Code 状态栏显示当前选中 / 聚焦的 Claude Code IDE 会话的请求平均输出速率。复用 Hub 现有会话选择规则，不根据工作区猜测某个聊天标签的身份。

用户已确认：不向官方 Claude Code 聊天界面注入内容，不修改官方扩展文件。

首版不实现逐 Token 实时解码测速，不接管 Claude 进程，不安装代理，不新增网络请求，不要求修改 Claude 用户配置或重启聊天。兼容已有终端 statusLine 采样。

## 2. 已验证依据与兼容边界

当前安装的 Claude Code 2.1.319 所生成的真实 IDE 会话 JSONL 包含：

- `api-request.id`、`api-request.timestamp`：请求关联标识及本地记录时间。
- `assistant.requestRef`：关联请求 ID。
- `assistant.message.id`、`assistant.message.usage.output_tokens`：消息身份与输出计数。
- `assistant.timestamp`：各响应内容块的本地记录时间。

同一请求 / 消息可以有多条 assistant 记录，并重复携带相同 usage。因此不能直接累加所有记录的 output_tokens。

本机只读验证曾得到 630 / 18.527 ≈ 34.0 tok/s。该结果证明数据可关联、可计算，不代表该数字已显示于 Hub，也不证明结束标记在所有版本都相同。

这些字段是当前会话文件的观测结果，不是已确认的官方稳定遥测 API。官方在线文档本轮访问失败；不得在说明中宣称跨版本保证。字段缺失时必须安全降级为无数据。

## 3. 速度口径

记录测速公式：

`tokensPerSecond = uniqueOutputTokens * 1000 / (lastAssistantTimestamp - requestStartTimestamp)`

- 分子：同一请求内按 message ID 去重的最终有效输出计数之和，不重复叠加内容块。按有效记录时间排序，同一消息使用最新计数；相同时间戳的计数冲突或按时间排序后计数回退，则整个请求不产生样本。单个请求若关联多个不同的响应模型，也不发布混合模型读数。
- 分母：请求开始记录时间至最后一个关联 assistant 内容块记录时间，不采用工具结果或下一请求的时间作为响应结束时间。
- 包含首 Token 等待、思考以及请求期间可能发生的网络 / 重试等待，受本地记录时机影响。
- 不另加 thinking_tokens，避免与 output_tokens 重复计数；保留上游 output_tokens 的口径。
- 不把用户审批等待、工具执行时间、整轮对话耗时作为某次请求的分母。

UI 名称为“最近响应平均速度”；记录来源在提示中明确为“会话记录估算”。界面正常格式为 `34.0 tok/s`，提示说明“含等待与思考时间，非实时解码速度”。

分母至少为 500ms，分子、分母、结果必须为有限正数。缺失 / 无效时间戳不得用 Date.now() 补出测速数据。

## 4. 响应完成与记录聚合

单条 assistant 记录不必代表整个响应已落盘。usage 和 stop_reason 可能在多个内容块上重复出现，不能仅看到正数 usage 或 end_turn 就无条件定稿。

聚合器按请求 ID 收集开始记录、消息计数、最晚 assistant 时间和模型。解析顺序不作为关联依据，支持请求记录晚于响应记录出现。

已落盘完成的确认采用保守边界：

1. 工具型响应：观察到该请求产生的全部工具调用对应的工具结果，并且候选中的全部 assistant 记录时间均不晚于该边界，可确认此前响应已结束；后续主会话请求若可从现有关联链证明顺序承接该响应，也可作为边界。仅有一个并发工具先完成不足以确认整个请求结束。
2. 文本最终响应：观察到经过真实记录顺序验证的回合完成标记，可确认候选响应；`cost-state` 可作为完成边界但不替代响应结束时间。
3. 对 `last-prompt` 等其他标记，实施前须验证其在真实记录中的顺序和用途；未验证的标记不作为完成证据。
4. 仅有 stop_reason、文件短暂不变或扫描结束，不作为可靠完成证据。缺少完成边界则保留“采样中 / 等待完成”，不发布假定已完成的速度。

多个请求并发时，按关联 ID 分开；不把某个后台请求的出现视为所有请求均已结束。若完成归属不明确，放弃该样本。工具错误或中断不自动变成成功的最终响应样本。

聚合器只保存计算所需的数字、关联 ID、模型、时间及必要完成边界，不额外持久化提示词、响应正文或完整请求对象。

## 5. 组件与数据流

### 5.1 独立的记录测速聚合器

新增不依赖 vscode 的小型 TypeScript 模块，消费已解析的记录，产出：

- 最近已完成的有效记录测速样本。
- 能力 / 采样状态：等待、采样中、可用、缺少所需字段。
- 样本来源、测量时刻、请求及响应模型身份。

聚合和校验可独立测试。不对现有大型 transcriptParser 做无关重构。

### 5.2 Transcript parser

在已有逐行读取循环中喂入聚合器，复用现有文件读取、缓存及失效机制，不为测速再次扫描完整 transcript。不更改原有 Token、任务、工具和模型解析语义。

`/clear` 等会话重置边界清除此前测速候选与结果。只聚合当前会话文件对应的主会话，不混入子代理文件或其他 sessionId 的记录。

### 5.3 Session manager 与来源选择

同时维护记录来源与终端 bridge 来源，再统一选择展示结果：

- 只使用当前会话、当前有效响应模型匹配的样本，不要求中转请求的配置模型名称等同于实际响应模型。
- 两种来源均有效时选择测量时间较新的；同时间优先记录来源。UI 提示展示实际来源与口径。
- 终端 sample watcher 更新不得把有效的记录来源样本覆盖成 undefined。
- 切换模型后，只有切换后且响应模型匹配的新样本才恢复显示，不能因模型后来切回而复活先前过期样本。
- 切换会话沿用既有焦点选择，立即重新渲染并清空前一会话的状态。

共享类型明确区分来源及采样状态。旧 bridge JSON 文件不强制改格式，在读取适配处标记终端来源。

### 5.4 UI 与按钮文案

- Hub 主速率位置与已有会话展示沿用当前布局，不新增独立大面板。
- 可用：显示最近响应平均 tok/s，提示来源、模型、采样时间及口径。
- 新请求进行中：标记“采样中”；若保留历史有效速度，明确标注“上次”，不可表现成当前实时数值。
- 无可用样本：显示 `—`，按数据状态提示等待响应完成或当前记录缺少字段，不声称模型速度为 0。
- VS Code 状态栏保留现有非极简预设行为；tooltip 说明来源以及上次 / 采样中状态，极简预设不新增速度。
- 将现有启用 / 停用命令与按钮准确标为“终端速率采集”，明确只管理 statusLine bridge。IDE 记录测速随会话解析自动工作。
- 停用终端采集不会停用 IDE 记录测速；确认框、成功通知及 README 必须说明这一点。
- 已启用终端采集但无样本时不重复展示“启用”诱导用户重复配置；展示“终端采集已启用，等待样本”。

所有新增或修改文案提供中英文；manifest 文案变化同步两份 package.nls 文件。动态模型和文本继续安全转义 / textContent 渲染。

## 6. 故障处理与资源管理

容忍 JSONL 半行、损坏记录、未知字段和暂时读不到文件。无效记录不抛出到 UI，也不产生 NaN、Infinity、负值或瞬时高值。缺少字段不通过提示词长度、字符数或整轮时间补算。

不新增常驻子进程或新 watcher，复用现有扫描节流和事件清理。内存只随既有一次解析范围的请求元数据增长；不在扩展全生命周期无界缓存全会话请求正文。

官方版本调整字段后，原有会话 / 任务能力继续工作，测速降级为无数据并说明限制。

## 7. 验证与验收

### 自动测试

使用确定性的临时 JSONL fixture 覆盖：

1. 正常请求与已确认完成响应，精确计数和耗时。
2. 同一消息多内容块及重复 usage，不重复计数。
3. 多请求、并发、乱序、请求与响应绑定隔离。
4. 请求未结束不发布新速度，历史样本明确保留或清除。
5. 工具完成边界与最终文本完成边界，不将工具等待计入分母。
6. 缺失身份、无效时间、负数、计数冲突、短于 500ms、中断和半行记录。
7. 清空、切换会话、模型及中转模型绑定。
8. bridge watcher 不擦除 transcript 样本，双来源新旧选择。
9. DOM / 状态栏状态和来源文案、安全转义、中英文 key 对齐。
10. 开关只控制终端采集，IDE 不依赖 bridge 已安装标记。

运行最窄相关测试后运行 npm test 和 npm run compile；更新 README 与 CHANGELOG。

### 当前 IDE 真实验收

在用户批准的安装 / 重载步骤后，使用当前 IDE 会话完成正常问答，选中对应 Hub 会话，实际检查面板与 VS Code 状态栏读数及提示。必要的安装或重载另行确认，不中断用户当前会话。

用同一请求的去重 Token 与时间戳复核读数，并验证新请求显示采样状态和会话切换不串值。不以模拟输入或单元测试代替真实 UI 验收。若环境不能驱动 / 查看 UI，明确记录未验证项。
